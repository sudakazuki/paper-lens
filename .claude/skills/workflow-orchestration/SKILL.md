# workflow-orchestration — メインの共通作法

本リポジトリの `write-article` が参照する契約を集約したもの（元キットのスキルが本リポジトリに同梱されていないための補完版）。`write-article` 側の記述と矛盾する場合はそちらを優先する。

## 作法

- **絶対パス引き回し**: ステップ間の受け渡しはすべて絶対パスで行う。Windows では `C:/Users/.../paper-lens/...` のようにドライブレター付きで渡す（Git Bash 形式 `/c/Users/...` は使わない）。
- **限定 Read**: メインはサブエージェントの生成物を全読みしない。ワークフロー側の「限定 Read 契約」テーブルにある見出しだけを読む。
- **サブエージェントの実行モード**: 各ステップは対応するサブエージェントを `Agent` ツールで起動し、入力（引数）は箇条書きで明示して渡す。並列指定のあるステップは単一メッセージ内で並列起動する。それ以外は前ステップの戻り値を受けてから順に起動する。
- **戻り値形式**: サブエージェントは最終メッセージに成果物の絶対パス（レビュアーは `<パス> PASS|FAIL`）を単一行で返す。メインはそれだけを次ステップへ渡す。
- **整合チェック失敗時の中断**: サブエージェントが中断レポート（入力不一致・生成失敗など）を返したら、メインは自動補正せずそのステップで停止し、内容をログに残してユーザーへ報告する。
- **メインがしないこと**: 成果物の中身を自分で書き換えない／レビュー判定を自分で下さない／サブエージェントの担当作業を肩代わりしない。

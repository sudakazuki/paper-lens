# multi-aspect-review — 観点別レビューループの共通契約

本リポジトリのエージェント定義・`write-article` が参照する契約を、それらの記述から集約したもの（元キットのスキルが本リポジトリに同梱されていないための補完版）。各エージェント定義・`write-article` 側の記述と矛盾する場合はそちらを優先する。

## 3 役

| 役 | 担当 | 責務 |
|---|---|---|
| 観点別レビュアー | article-reviewer / image-reviewer / html-reviewer | 渡された 1 観点だけに閉じて対象を点検し、レポートを Write して `PASS` / `FAIL` を返す。対象ファイルは書き換えない。 |
| 再生成 author | article-writer / article-image-generator / article-html-author | 受け取ったレポート 1 本のうち、自担当ファイル宛ての指摘だけを反映して上書き再生成し、ログへ追記する。 |
| オーケストレーター | write-article のメイン | 観点ごとにレビュアーを単一メッセージ内で並列起動し、戻り値で PASS/FAIL を集約。FAIL があれば該当 author を再生成起動し、iteration を進めて再レビュー。反復上限・打ち切り時の扱いは呼び出し側ワークフローに従う。 |

## 観点別レビュアー契約

### 入力

- `review-aspect`: 担当観点（1 つ）
- 点検対象ファイルの絶対パス（＋観点ごとの参照資料）
- `out`: レポート出力先の絶対パス
- `previous-review-path`: 2 周目以降のみ。前周回の同観点レポート

### 重大度と PASS/FAIL

- 各指摘を **重大 / 中 / 軽微** に区分する。
- 重大または中が 1 件でもあれば **FAIL**。軽微のみ（または指摘なし）なら **PASS**（軽微はコメントとして残す）。

### レポートテンプレ

```markdown
# レビューレポート: <review-aspect>（iteration <n>）

## 判定
PASS | FAIL（重大 x 件 / 中 y 件 / 軽微 z 件）。判定理由を 1〜3 文で。

## 解消済みの前回指摘
（差分レビュー時のみ。前回指摘のうち解消したものを列挙）

## 未解消の指摘 / 新規指摘

### 指摘 1
- 重大度: 重大 | 中 | 軽微
- 対象ファイル: <絶対パス>
- 箇所: <見出し・段落・要素など特定できる位置>
- 問題: <何が問題か>
- 期待される状態: <どうなっていれば解消か。肯定形で具体的に>
- 状態: 新規 | 未解消

## 軽微なコメント
（任意）
```

- 「対象ファイル」は必ず **絶対パス**（オーケストレーター・author が機械的に照合するため）。
- 指摘がない場合も `## 未解消の指摘 / 新規指摘` 見出しは置き、「なし」と書く。

### 差分レビューモード（`previous-review-path` あり）

1. 前周回レポートの各指摘について、対象ファイルの該当箇所を確認し解消状況を判定する。
2. 解消済みの指摘は `## 解消済みの前回指摘` に列挙する。
3. 未解消の指摘は `状態: 未解消` を付け、指摘文をそのまま引き写して再掲する。
4. 新規指摘は **重大のみ** 記載する（中・軽微の新規指摘は書かない。揺り戻し防止）。

### 戻り値

最終メッセージに `<out の絶対パス> PASS` または `<out の絶対パス> FAIL` を単一行で返す。

## 再生成 author 契約（4 ステップ）

入力: `review-report-path`（レポート 1 本の絶対パス）、`regeneration-log-path`

1. 自担当ファイルの現状と、根拠資料（記事本文・解析結果など）を Read する。
2. レポートの `## 未解消の指摘 / 新規指摘` 配下から、「対象ファイル」が自担当ファイルの絶対パスと一致する指摘だけを抽出する（一致しない指摘は無視）。
3. 抽出した指摘の「期待される状態」を満たすよう自担当ファイルを上書き再生成する。指摘されていない箇所は壊さない（最小差分）。
4. `regeneration-log-path` の末尾に追記する（上書き禁止）: 対象レポートのファイル名／対応した指摘件数／未対応の指摘とその理由。

戻り値: 再生成した自担当ファイルの絶対パスを単一行で返す。

## オーケストレーター契約

- iteration は 1 から始める。レポートは `<prefix>-<iteration>_<aspect>.md` の命名で観点ごとに出力させる。
- 全観点のレビュアーを **単一メッセージ内で並列起動** する。
- 判定は戻り値で集約し、レポート本文は必要時に `## 判定` 見出しのみ限定 Read する。
- FAIL があれば、該当 author に渡すレポートを選び（選定規則は呼び出し側ワークフローに従う）、再生成 → iteration+1 → 2 周目以降は `previous-review-path` 付きで再レビュー。
- 反復上限・打ち切り時の扱いは呼び出し側ワークフローの規定に従う。
